# ElementalCommand GDD

- 문서 버전: 2.0
- 프로젝트 버전: 0.7.2
- 최종 동기화: 2026-09-23
- 구현 기준: `src`, `tests`, `package.json`
- 플랫폼: 브라우저, Windows 로컬 런처 보조

## 제품 정의

5속성 지휘관을 최대 4명 편성하고 5×6 헥스 보드에서 보석 경로를 연결해 기본 공격·스킬·약점 파괴를 실행하는 세로형 전술 퍼즐 RPG다. 짧은 전투에서 `편성 → 보석 공급 → 명령 선택 → 결과 회고 → 덱 수정`이 반복되는 것이 핵심이다.

## 핵심 사용자 문제

플레이어는 스킬 요구 보석, 적 약점 카운터, 지휘관 속성에 따른 보석 출현 가중치를 동시에 판단한다. 행동 전 예상 결과뿐 아니라 전투 후 어떤 명령과 속성 공급을 바꿔야 하는지가 이어지지 않으면 같은 실수를 반복하게 된다. 따라서 결과 화면은 점수판이 아니라 다음 덱·명령 선택으로 돌아가는 연결 지점이어야 한다.

## 핵심 루프

스테이지 선택 → 지휘관 최대 4명 편성 → 파티 속성에 따른 보석 가중치 생성 → 활성 지휘관·스킬 확인 → 헥스 경로 드래그 → 기본 공격 또는 명령 발동 → 적 약점·타이머 대응 → 승패 회고 → 재도전·편성 수정·스테이지 선택.

## 전투 규칙

| 항목 | 현재 규칙 |
|---|---|
| 보드 | 5열×6행 헥스 보드 |
| 속성 | 불, 물, 자연, 빛, 어둠 |
| 편성 | 지휘관 최대 4명 |
| 보석 공급 | 기본 균등 가중치에 편성 지휘관 속성을 가산 |
| 명령 | 선택 스킬의 보석 순서를 완성하면 스킬, 실패하면 기본 공격 |
| 약점 | 적별 약점 보석 카운터를 채우면 약점 파괴 및 공격 타이머 초기화 |
| 적 공격 | 타이머 종료 시 파티 피해와 보드 장애물 추가 |
| 승리/패배 | 모든 적 처치 / 모든 지휘관 전투 불능 |

## 행동 전 정보

스킬 선택 영역과 명령 결과 예측 영역을 분리한다. 선택한 명령은 목표 적, 상성, 약점 카운터 전후, 예상 피해, 약점 파괴 보너스, 다음 전술 의미를 표시한다. 색상만 사용하지 않고 속성 문자와 텍스트를 병행한다.

## 결과→다음 덱/명령 판단

전투 기록은 시도한 명령명, 요구 보석, 지휘관 속성, 약점 기여도를 저장한다. 결과 화면은 다음 정보를 표시한다.

- 최고 효율 명령과 낭비된 명령
- 다음 전투에서 먼저 재현할 명령
- 낭비된 명령의 요구 보석 빈도로 계산한 보강 속성
- `Retry`, `Edit Party`, `Stages`의 명시적 다음 행동

결과 화면은 자동으로 사라지지 않는다. `Edit Party`를 선택하면 덱 보강 조언이 편성 화면 상단에 전달된다. 정답이나 편성을 자동 적용하지 않고 판단 근거와 다음 실험 한 가지만 제공한다.

## 화면 흐름

| 화면 | 역할 |
|---|---|
| Boot | 정식 이미지·오디오·UI 자산 로딩 |
| StageSelect | 스테이지와 적 구성 선택 |
| PartySelect | 지휘관 속성·스킬·능력치 비교, 최대 4명 편성, 이전 전투 보강 조언 확인 |
| Battle | 헥스 경로, 스킬 선택, 명령 미리보기, 약점·타이머 전투 |
| Battle Result Overlay | 전투 회고, 다음 명령·덱 보강, 재도전·편성 수정·스테이지 이동 |

## UI/UX 원칙

- 기존 어두운 네이비 패널, 밝은 청록·금색 강조, 포트레이트·보석·버튼 자산을 유지한다.
- 플레이어가 읽어야 할 명령·수치·조언은 실제 텍스트로 유지한다.
- 480×854 세로 화면에서 전투 보드, 파티, 스킬 선택, 명령 예측 영역을 겹치지 않게 분리한다.
- 결과 화면은 자동 전환하지 않고 플레이어의 명시적 다음 행동을 기다린다.
- 새 이미지 없이 기존 `ui-deploy-card-selected`, `ui-button-ready` 자산을 재사용한다.

## 검증 현황

2026-09-23 기준 집중 테스트 3개 파일·18개와 전체 14개 파일·82개 테스트가 통과했다. `npm run build`가 통과했고 Impeccable 정적 감지는 0건이었다. 빌드 결과 JavaScript 청크 약 1.53MB가 500kB를 넘는다는 경고가 남았다. 의존성 강제 업그레이드와 보안 감사, 포터블 패키징, Drive 배포는 실행하지 않았다.

## 복원 소스 계보

- 현재 복원 소스: v0.7.2
- 프로젝트 루트 실행파일: `ElementalCommand_v0.6.0_portable.exe`
- Drive 실행파일: `27_ElementalCommand_v0.10.2_portable.exe`

Drive에는 더 높은 버전의 실행파일만 있으며 대응 소스는 확인되지 않았다. 실행파일 버전만으로 현재 소스의 상위 계보를 단정하거나 소스를 덮어쓰지 않는다.

## 알려진 리스크와 다음 우선순위

- 실제 승리·패배 완주 후 결과 버튼 입력과 480×854 줄바꿈은 수동 미검증이다.
- 편성 조언은 요구 보석 빈도 기반이며 적 스테이지별 승률·생존 데이터를 아직 반영하지 않는다.
- 보안 감사와 의존성 업데이트는 별도 승인·검증 범위가 필요하다. 이번 작업에서 강제 업그레이드하지 않았다.
- 다음 개선은 적 약점 분포와 파티 생존 결과를 함께 사용해 보강 속성의 근거를 확장하는 것이다.
